# Security reports

For vulnerabilities that expose accounts, credentials, arbitrary file access or remote code execution, use this repository's **Security → Report a vulnerability** private reporting flow. Do not post working exploits, credentials or other players' data in a public issue.

For ordinary bugs, crashes and gameplay abuse, open an issue with the release version, reproduction steps and a minimal redacted log excerpt. Never attach the entire application profile. Host removal and local mute controls are available for disruptive players; this project does not operate global account bans.

Only the newest public release is maintained. The game is peer-hosted and cannot guarantee cheat-free results. See [online architecture and data handling](docs/ONLINE_AND_UPDATES.md).
