Scope: every client screen, match screen, overlay, tooltip, modal, transition, and interactive state. This is a restoration checklist, **not an acceptance report**. ## Highest-priority differences confirmed at restoration start

These findings explain the restoration work, not the latest completion status. Source changes and partial validation since that point are recorded separately below.

1. **Match geometry:** original `style.css:136` uses a 52 px top strip, left traits, central board, right tamers, and a compact bottom economy/shop strip. In the inspected 1600×900 reference, the arena is x=248..1328 and y=52..758 (1080×706), leaving 142 px for the shop. At the inventory start, native `MatchScreen.cs` used `Top=144`, `Height=size.Y-506`, and a 338 px shop window: only 394 px of arena height at the same resolution. Restore the original hierarchy before tuning individual cards. Preserve board interactions and render/input coordinate agreement.
2. **Choice context:** original carousel and offers occupy/dim the arena while the surrounding HUD stays visible. Native `MatchScreen.Carousel.cs` starts a full-window carousel. Restore the contextual modal and all waiting, taken, peek, and completion states, including compact-window scrolling.
3. **Client shell:** original `index.html:185`, `theme.js`, and `client.js:238` use one navigation row, an angled PLAY action, Bits/status, profile level ring, and a persistent/collapsible social column. Native began this pass with two rows of generic rectangular navigation buttons. The old shell and the old in-match HUD have distinct layouts; copying the client header into matches is not parity.
4. **Result navigation:** original `client.js:995` places results in `#homeResults` under the client chrome and retains them while visiting another page; `go`/`back` at lines 133/155 do not discard the result. Native `MatchScreen.Postgame.cs` used a full-window result, limited the client overlay to Profile/Store, and `NavigateClient` dismissed results when leaving that overlay. Verify Home → Settings/Profile/Store → back → results, explicit close, Play Again, Spectate, and Leave independently.
5. **Component hierarchy:** apply original typography, art placement, borders, rarity colors, disabled/selected states, and density consistently. Merely increasing all text or adding gold outlines to existing ImGui windows will preserve the wrong proportions. Original match controls use a restrained slate HUD; original client pages use the navy/gold artwork-led launcher shell.

## Follow-up review and validation limits

All 101 grouped state rows below remain open. The active restoration has corrected substantial source structure, but the following evidence is partial and must not be presented as whole-client parity.

- **Results:** `native/artifacts/ui-parity-postgame/{normal,minimum,short}/test.log` reports 13 real mouse scenarios at each size (39 total), including Solo/Duos victory/elimination, payout idempotence, retained results through Profile/Store/Settings/Lobbies, explicit close, Again, Leave, and Spectate. The normal fixture is **1440×900**, not 1600×900. Same-size independent image comparison found the restored two-column arrangement substantially follows the original; minimum native `result.0.png` clips the lower standings while the original shows all eight. The owner has since changed the first-row budget and added an assertion for eight fully visible rows at height 760 or greater, but this follow-up has not seen the rebuilt capture. The native three-column layout above width 1500 also needs a new capture. Names, payouts, traits, and compositions differ between fixtures and are not by themselves layout defects.
- **Shell navigation:** source now contains `RememberClientRoute`/`BackClient`, desktop social collapse, and `CollectionModalVisible` in navigation blocking. These address the first review's missing back stack and purchase/hatch navigation escape. Verify Home → Collection → Profile → Escape → Collection → Escape → Home with real input, plus attempts to navigate or join a lobby during purchase, hatch, and reveal. Direct cross-page links such as Store → Locker, linked sound → Store, and Loot → Farm also need history coverage; they bypassed the new history calls at the follow-up read and were reported to the shell owner.
- **Overlay context:** `FarmTrainingOverlay` now draws training over the retained, disabled farm scene and resident controls. The original training references under `extra/` are available for paired validation. After the follow-up reported the missing HUD beneath pause/menu, `PausePanel` was updated to draw the disabled Header/Roster/Sidebar before the scrim. Both corrections still require paired images and input checks; rendering a dark scrim alone does not restore the original context.
- **Update notice:** the original `renderUpdate` runs across client pages. At the follow-up read, native `UpdatePanel` was called from Home/About only, before Collection drawing where that route shares Home; Settings, Profile, Farm, Play, Codex, and retained Postgame bypass it. The owner was notified to validate global client placement, Later/restart behavior, overlay stacking, and no interruption of a live match.
- **Match evidence:** the match owner reports 16 real tooltip routes at each of 1600×900, 1100×760, and 1342×670 with 48 images in `native/artifacts/ui-parity-match/`. This covers shop/bench/trait/combat tooltip paths, not the whole match. A compact standings defect was found visually and corrected in source, pending rebuilt captures. The broader match smoke was blocked at `Home/hero-initial`; the new inventory drawer, item equip/drop, full bench, overflow, and compact HUD still require acceptance runs.
- **Remaining cross-cutting coverage:** all conditional offers in the matrix, multiplayer join/leave/reconnect states, short-window lobby and training overlays, fresh first boot, update/error/data dialogs, 1920×1080, and OS scaling require explicit paired evidence. Successful ordinary-page screenshots do not establish these states.
